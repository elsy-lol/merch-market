Анализ проекта "STREET PLAYER"
================================

ОБЩАЯ ИНФОРМАЦИЯ
-----------------

STREET PLAYER - это музыкальный плеер в тёмном киберпанк-стиле, реализованный в двух независимых версиях:

  Платформа           Папка                Язык           Фреймворк                    Аудиодвижок
  Desktop (Windows)   Player/              C# 12+         Avalonia 11.1 / .NET 10      NAudio 2.2.1
  Android             PlayerAndroid/       Kotlin 1.9.22  Jetpack Compose + Material3  AndroidX Media3 (ExoPlayer) 1.2.1


СТРУКТУРА ФАЙЛОВ
-----------------

Desktop Player (Player/):

  Program.cs              Точка входа приложения
  App.axaml + .cs         App-класс, тема, иконки, ресурсы
  MainWindow.axaml        XAML-разметка окна (197 строк)
  MainWindow.axaml.cs     Вся логика плеера (309 строк)
  Player.csproj           Конфигурация проекта
  Player.csproj.user      Настройки VS (устаревшие)

Android Player (PlayerAndroid/):

  MainActivity.kt                      Activity, разрешения, запуск сканирования
  service/PlaybackService.kt           Фоновая служба Media3
  ui/PlayerViewModel.kt                ViewModel: состояние, плейлист, управление
  ui/PlayerScreen.kt                   Compose UI: экраны, треклист, пульт (528 строк)
  data/MusicScanner.kt                 Сканер аудио через MediaStore
  data/Track.kt                        Data-класс трека
  ui/theme/Color.kt                    Цветовая палитра
  ui/theme/Theme.kt                    Тёмная тема Material3
  AndroidManifest.xml                  Разрешения, компоненты
  build.gradle.kts (app + root)        Конфигурация Gradle


ПЛЮСЫ (СИЛЬНЫЕ СТОРОНЫ)
-------------------------

Общие:
  1. Единый визуальный стиль - обе версии имеют одинаковый тёмный киберпанк-дизайн
     (чёрный фон, синий акцент #3A86FF), создавая узнаваемый бренд.
  2. Современный стек - используются актуальные версии технологий
     (Avalonia 11.1, .NET 10, Jetpack Compose, Material3, Media3).
  3. Векторные иконки SVG - все иконки плеера встроены как StreamGeometry пути,
     нет внешних зависимостей.
  4. Тёмная тема + акриловый blur на десктопе - красивые визуальные эффекты
     через ExperimentalAcrylicBorder.

Desktop (C#):
  5. CancellationTokenSource - корректная отмена сканирования.
  6. Dispatcher.UIThread - правильное переключение на UI-поток.
  7. Try/catch при работе с файлами - обработка UnauthorizedAccessException
     через IgnoreInaccessible.
  8. INotifyPropertyChanged - реализован на PlaylistItem.

Android (Kotlin):
  9. Чистая архитектура MVVM - ViewModel + Compose + Service, хорошее разделение.
 10. Фоновая служба Media3 - корректно реализована MediaSessionService
     с foregroundServiceType="mediaPlayback".
 11. Правильные разрешения - обрабатываются и READ_MEDIA_AUDIO (Android 13+),
     и READ_EXTERNAL_STORAGE (старые версии).
 12. Корутины - асинхронные операции через viewModelScope и lifecycleScope.
 13. Поиск работает - фильтрация треков по названию и исполнителю.
 14. Пустое состояние - отображается UI, когда треков нет.
 15. Состояния плеера - реализованы Shuffle, Repeat, AutoPlay.


МИНУСЫ (ПРОБЛЕМЫ)
------------------

Критические:
  1. Поиск на десктопе не работает - метод UpdateFilter() в MainWindow.axaml.cs:297
     пустой. Поле поиска есть, но ничего не происходит.
  2. Нет уведомления на Android - PlaybackService не создаёт NotificationChannel
     и не показывает foreground-уведомление, хотя это обязательно для Android 13+.
  3. Загрузочная анимация - фейк. StartInitialAnimation() просто крутит прогресс-бар
     от 30% до 100% с Task.Delay, не отражая реальный прогресс.

Архитектурные:
  4. Монолит на десктопе - вся логика (309 строк) в одном code-behind
     MainWindow.axaml.cs. Нет MVVM, нет разделения, невозможно тестировать.
  5. Нет слоя Repository на Android - MusicScanner вызывается напрямую из
     MainActivity, а ViewModel получает треки извне вместо того, чтобы сама их
     запрашивать.
  6. Плейлист на Android пересоздаётся целиком - playTrack() каждый раз чистит
     и заново добавляет все отфильтрованные треки в ExoPlayer. Неэффективно для
     больших библиотек.
  7. Совпадение треков по URI - updateCurrentTrack ищет трек по mediaUri?.path,
     что хрупко и может сломаться при разной кодировке URI.
  8. Нет общей логики между платформами - два полностью независимых codebase,
     хотя делают одно и то же. Нет shared-кода.

Отсутствующие функции:
  9. Нет сохранения плейлистов - всё в памяти. После перезапуска нужно
     сканировать заново.
 10. Нет обложек альбомов - не парсятся ID3-теги, не отображаются обложки.
 11. Нет эквалайзера/аудиоэффектов - базовая функция для плеера отсутствует.
 12. Нет локализации - весь текст на русском, без strings.xml или .resx.
 13. Нет тестов - ни одного unit, UI или integration теста.
 14. Нет обработки битых файлов - на десктопе кривой/DRM-файл может уронить плеер.
 15. "СЕЙЧАС ИГРАЕТ" вместо исполнителя - на десктопе lblArtist.Text выводит
     статус вместо имени артиста.

Технический долг:
 16. Player.csproj.user ссылается на Form1.cs - мусор от Windows Forms шаблона.
 17. Нет .gitignore - bin/, obj/, build/, .gradle/ будут коммититься.
 18. Глубина сканирования 4 - MaxRecursionDepth = 4 может пропустить глубокие папки.
 19. Version Catalog не используется - версии зависимостей разбросаны по
     build.gradle.kts.
 20. JavaVersion.VERSION_1_8 - Kotlin 1.9.22 на JVM 1.8, что ограничивает
     некоторые фичи stdlib.


РЕКОМЕНДАЦИИ ПО УЛУЧШЕНИЮ
--------------------------

Срочные исправления:
  1. Реализовать поиск на десктопе - дописать UpdateFilter(): фильтровать playlist
     по txtSearch.Text и обновлять playlistBox.ItemsSource.
  2. Добавить уведомление на Android - создать NotificationChannel в
     PlaybackService.onCreate(), показывать foreground-нотификацию с кнопками
     play/pause.
  3. Удалить/исправить фейковую анимацию - либо показывать реальный прогресс,
     либо убрать.
  4. Удалить Player.csproj.user - это мусор, VS пересоздаст при необходимости.

Архитектурные улучшения:
  5. Переписать десктоп на MVVM - вынести логику в PlayerViewModel. Использовать
     ReactiveUI или CommunityToolkit.Mvvm для биндинга.
  6. Добавить Repository на Android - создать MusicRepository, вызывать его из
     ViewModel, а не из Activity.
  7. Оптимизировать плейлист на Android - не пересоздавать список каждый раз,
     а поддерживать единый плейлист в ExoPlayer и перематывать к нужному индексу.
  8. Улучшить сопоставление треков - передавать ID трека вместе с MediaItem
     вместо сопоставления по URI.

Новые функции:
  9. Сохранение плейлистов - JSON-файл на десктопе, Room БД на Android.
 10. Обложки альбомов - TagLibSharp на десктопе, MediaMetadataRetriever на Android.
 11. Эквалайзер - NAudio поддерживает эффекты; на Android - AudioEffect с Equalizer.
 12. Локализация - вынести все строки в .resx (C#) и strings.xml (Kotlin).
 13. Парсинг ID3-тегов - показывать реальное имя исполнителя, альбом, жанр.

Качество кода:
 14. Добавить тесты - ViewModel на Android (с mock ExoPlayer), логика сканирования
     и плейлиста на десктопе.
 15. Обработка ошибок - обернуть все операции с файлами и плеером в try/catch
     с показом сообщения пользователю.
 16. Добавить .gitignore - исключить bin/, obj/, build/, .gradle/, local.properties,
     *.user, .vs/.
 17. Инициализировать Git - защитить код от случайной потери.
 18. Использовать Version Catalog - вынести версии зависимостей в libs.versions.toml.

DevOps:
 19. CI/CD - GitHub Actions или GitLab CI для автоматической сборки обеих версий.
 20. Подпись Android-приложения - настроить подпись APK для публикации.
