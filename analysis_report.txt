1. ОБЩАЯ СТРУКТУРА ПРОЕКТА
================================================================================

Проект состоит из 5 подпроектов, разделённых на два независимых направления:

  МУЗЫКАЛЬНЫЙ ПЛЕЕР (STREET PLAYER):
    (1) Плеер/Player/            — Десктопный аудиоплеер (C# 12, Avalonia 11, .NET 10)
    (2) Плеер/PlayerAndroid/     — Мобильный аудиоплеер (Kotlin, Jetpack Compose, Media3)
    (3) Плеер/Player.Tests/      — Модульные тесты (xUnit, .NET 10)

  ИНТЕРНЕТ-МАГАЗИН (STICKER MERCH):
    (4) backend/                 — Django REST API (Python 3.11, PostgreSQL)
    (5) frontend/                — React SPA (TypeScript + Vite, React 19)
    (6) MerchMarketRN/           — React Native (Expo, устаревающий, дублирует frontend)

  ОБЩЕЕ:
    analysis_report.txt          — Данный файл
    .opencode/                   — Конфигурация opencode

2. ДЕСКТОПНЫЙ ПЛЕЕР (C# / Avalonia / .NET 10)
================================================================================

  Технологии:
    - .NET 10 (net10.0-windows)
    - Avalonia 11.1 (FluentTheme, AcrylicBlur, Fonts.Inter)
    - NAudio 2.2.1 (WaveOutEvent, AudioFileReader)
    - CommunityToolkit.Mvvm 8.3.2 (source-generators: [ObservableProperty], [RelayCommand])
    - TagLibSharp 2.3.0 (ID3-теги, обложки)

  Архитектура:
    Program.cs
      └─ App.axaml / .axaml.cs
           └─ MainWindow.axaml / .axaml.cs (View + code-behind)
                └─ PlayerViewModel.cs (ObservableObject, 488 строк)
                     ├── PlaylistItem.cs (модель трека, INotifyPropertyChanged)
                     ├── EqualizerSampleProvider.cs (DSP: BiQuadFilter, бас 80Гц + вч 6000Гц)
                     ├── NAudio: WaveOutEvent + AudioFileReader
                     └── TagLibSharp (ID3 + обложки)

  Функции:
    - Play/Pause, Next/Previous, перетаскивание ползунка (seek)
    - Поддержка: .mp3, .wav, .flac, .ogg, .aac, .wma, .m4a
    - Эквалайзер: бас (PeakingEQ 80Гц) + вч (PeakingEQ 6000Гц), ±24dB
    - Сканирование дисков (Fixed/Removable, глубина 4)
    - Выбор папки / добавление файлов с дедупликацией
    - Фильтрация плейлиста по поиску (название + путь, регистронезависимо)
    - Сохранение/загрузка плейлиста: JSON в %APPDATA%\STREET PLAYER\
    - Режимы: Repeat (один), AutoPlay (все подряд), Shuffle (случайно)
    - Обложки альбомов из ID3-тегов (TagLibSharp)
    - Акриловый blur (AcrylicBlur), тёмная тема с синим акцентом #3A86FF
    - Оверлей загрузки (но IsLoading/LoadingProgress никогда не устанавливаются)
    - Векторные иконки: Play, Pause, Next, Prev, Repeat, Shuffle, AutoPlay, Search

  Тесты (Player.Tests, xUnit):
    - 18 тестов в PlayerViewModelTests.cs
    - Покрытие: пустое состояние, команды без плейлиста, очистка,
      взаимоисключение Shuffle/Repeat/AutoPlay, иконки, поиск, громкость,
      дедупликация, начальные состояния HasCoverArt/HasAlbumText
    - НЕ тестируется: собственно воспроизведение, эквалайзер, сканирование,
      загрузка/сохранение плейлиста, парсинг тегов

  Известные проблемы:
    - Не чистый MVVM: ViewModel создаётся в code-behind MainWindow
    - Обложки без кэширования (декодируются каждый раз)
    - Ошибки воспроизведения: только базовый try/catch (пропуск трека)
    - Player.csproj.user содержит мусор (ссылка на Form1.cs от WinForms)
    - UnitTest1.cs — пустая заглушка

4. БЭКЕНД (Django REST API + Custom Admin)
================================================================================

  Технологии:
    - Python 3.11, Django 5.2, DRF, djangorestframework-simplejwt
    - django-cors-headers, psycopg2
    - PostgreSQL (merchmarket_db, localhost)

  Архитектура:
    config/urls.py
      ├── /admin/    → django.contrib.admin (ModelAdmin для всех моделей)
      ├── /cp/       → shop.admin_urls → shop.admin_views (16 views)
      └── /api/      → shop.urls → shop.views (DRF, 7 APIView-классов)

  ── 4.1 МОДЕЛИ ──────────────────────────────────────────────────────

    Таблица             Модель           managed  Описание
    ───────────────────────────────────────────────────────────────
    users_user          ShopUser         Нет      Пользователи (JWT auth)
    shop_creator        Creator          Нет      Музыкальные исполнители
    shop_category       Category         Нет      Категории товаров (self-ref parent)
    shop_product        Product          Нет      Товары
    shop_productvariant ProductVariant   Нет      Варианты (размер/цвет/stock/SKU)
    shop_productimage   ProductImage     Нет      Изображения
    shop_userprofile    UserProfile      Да       Доп. профиль (display_name, avatar..)
    shop_order          Order            Да       Заказы (user_id, total, status)
    shop_orderitem      OrderItem        Да       Позиции заказа (денормализовано)
    shop_supply         Supply           Да       Привозы (+stock через F())

    Ключевые особенности:
    - 6 таблиц с managed=False — наследие внешней БД; Django не управляет миграциями
    - 4 таблицы (UserProfile, Order, OrderItem, Supply) — managed=True, Django управляет
    - ShopUser НЕ extends AbstractUser — кастомная модель, зеркалящая users_user
    - UserProfile привязан через user_id (IntegerField, не ForeignKey)

  ── 4.2 API-ЭНДПОИНТЫ (DRF, /api/) ─────────────────────────────────

    Метод  Путь                          Auth      Назначение
    ─────────────────────────────────────────────────────────────────
    GET    /api/artists/                 Публично  Список исполнителей
    GET    /api/artists/<slug>/          Публично  Детали + товары
    GET    /api/merch/?artist_slug=      Публично  Товары (фильтр)
    POST   /api/checkout/                JWT       Оформление заказа
    POST   /api/auth/register/           Публично  Регистрация
    POST   /api/auth/login/              Публично  Вход
    POST   /api/auth/token/refresh/      Публично  Обновление JWT
    GET    /api/auth/profile/            JWT       Профиль + статистика
    PUT    /api/auth/profile/            JWT       Обновление профиля

    Аутентификация: JWT (simplejwt), access=2ч, refresh=7дн.
    CORS: Разрешены все origins (DEBUG=true).

    Сериализаторы:
    - CreatorListSerializer / CreatorDetailSerializer — с avatar_color, is_musician
    - ProductItemSerializer — вычисляемые поля через SerializerMethodField:
      condition, condition_display, size, stock, is_original, image_sticker_type,
      sticker_color (маппинг категорий на стикер-типы: tshirt/hoodie/cap/vinyl/...)
    - RegisterSerializer / LoginSerializer / ProfileUpdateSerializer — plain Serializer
    - CheckoutSerializer — nested-валидация items[{id, quantity}]
    - OrderSerializer / OrderItemSerializer — для истории заказов

    Checkout flow:
      1. Принимает [{id, quantity}] → находит ProductVariant по product_id
      2. Проверяет stock, декрементит через variant.stock -= quantity
      3. Создаёт Order (status='processing') + OrderItem'ы
      4. Возвращает order_id и сообщение

  ── 4.3 КАСТОМНАЯ АДМИНКА (function views, /cp/) ────────────────────

    Все 16 view декорированы @staff_member_required (редирект на /admin/login/).

    URL                              Назначение
    ─────────────────────────────────────────────────────────────────
    /cp/                             Дашборд (статистика: заказы/выручка/
                                      товары/артисты/пользователи + последние
                                      заказы + low-stock товары)
    /cp/artists/                     Список артистов (с product_count)
    /cp/artists/add/                 Создание артиста
    /cp/artists/<id>/edit/           Редактирование
    /cp/artists/<id>/delete/         Удаление (POST)
    /cp/products/                    Список товаров (с total_stock)
    /cp/products/add/                Создание + variant (size/stock/SKU)
    /cp/products/<id>/edit/          Редактирование
    /cp/products/<id>/delete/        Удаление (POST)
    /cp/orders/                      Список заказов (фильтр по статусу)
    /cp/orders/<id>/                 Детали + смена статуса (POST)
    /cp/supplies/                    История привозов
    /cp/supplies/add/                Добавление привоза (+stock через F())
    /cp/categories/                  Список категорий
    /cp/categories/add/              Создание (с parent)
    /cp/categories/<id>/edit/        Редактирование
    /cp/categories/<id>/delete/      Удаление (POST)
    /cp/users/                       Список пользователей

    Шаблоны (12 шт, admin2/):
    - base.html (411 строк) — тёмная тема, sidebar-навигация, CSS-переменные,
      Inter/Unbounded/Caveat шрифты, золотые градиенты, responsive sidebar
    - dashboard.html, artists.html, artist_form.html, products.html,
      product_form.html, orders.html, order_detail.html, supplies.html,
      categories.html, category_form.html, users.html
    - Все на русском, с {% empty %} для пустых состояний
    - Подтверждение удаления через JS confirm()

  ── 4.4 DJANGO ADMIN (/admin/) ──────────────────────────────────────

    Все 10 моделей зарегистрированы:
    - CreatorAdmin: prepopulated slug, поиск по name/slug
    - ProductAdmin: stock_total (сумма по variants), фильтры по type/condition/status/creator
    - ProductVariantAdmin: фильтры по size/color
    - OrderAdmin: date_hierarchy по created_at, фильтр по status
    - SupplyAdmin: date_hierarchy, фильтр по supplier
    - ShopUserAdmin: поиск по username/email, фильтры is_staff/is_active

  ── 4.5 ИЗВЕСТНЫЕ ПРОБЛЕМЫ БЭКЕНДА ─────────────────────────────────

    - DEBUG=true, ALLOWED_HOSTS=['*'], CORS_ALLOW_ALL_ORIGINS=true — опасно для прода
    - Пароль БД (Mars2020) и SECRET_KEY в открытом виде в settings.py
    - UserProfile.__str__() обращается к self.user.username, но user_id — IntegerField
      (не ForeignKey). Вызовет ошибку при display_name = пустой
    - ProductItemSerializer.get_size()/get_stock() берут только variants.first()
      (не обрабатывают множественные варианты)
    - Мок-данные во фронтенде дублируют реальные данные из БД
    - Нет MEDIA_URL/MEDIA_ROOT для изображений
    - seed_pg.py использует сырой SQL вместо Django ORM
    - ShopUser — не AbstractUser, что усложняет интеграцию со стандартным admin

8. ИЗВЕСТНЫЕ ПРОБЛЕМЫ И ТЕХНИЧЕСКИЙ ДОЛГ
================================================================================

  🔴 КРИТИЧЕСКИЕ:
    - Android PlaybackService не вызывает startForeground() — IllegalStateException
    - PlaybackService пересоздаёт весь плейлист при каждом треке (неэффективно)
    - DEBUG=true + ALLOWED_HOSTS=['*'] + CORS_ALLOW_ALL_ORIGINS в проде
    - Пароль БД и SECRET_KEY в открытом виде в settings.py
    - UserProfile.__str__() упадёт при пустом display_name (user — IntegerField)

  🟡 ВАЖНЫЕ:
    - Нет .gitignore (bin/, obj/, build/, .gradle/, local.properties, *.user)
    - Нет CI/CD (GitHub Actions, GitLab CI)
    - Нет обработки изображений (MEDIA_URL/MEDIA_ROOT)
    - seed_pg.py использует сырой SQL вместо ORM
    - ShopUser не AbstractUser — две таблицы пользователей
    - Десктоп: не чистый MVVM, обложки без кэширования, глубина сканирования 4
    - Android: нет эквалайзера, нет сохранения позиции, Java 1.8 target
    - IsLoading/LoadingProgress в десктопе никогда не устанавливаются
    - Player.csproj.user и UnitTest1.cs — мусор

  🟢 КОСМЕТИЧЕСКИЕ:
