                        1. ОБЩАЯ СТРУКТУРА ПРОЕКТА
═══════════════════════════════════════════════════════════════════════════════

Проект представляет собой маркетплейс мерча российских рэп-исполнителей.
Состоит из трёх стеков:

  ┌─ Frontend ─────────────────────────────────────────────────────────────────┐
  │  Vite 5 + React 18 + React Router 7                                       │
  │  Порт: 5173 │ Сборка: Vite │ Язык: JSX (не TypeScript)                    │
  └────────────────────────────────────────────────────────────────────────────┘
         │ HTTP
         ▼
  ┌─ Backend ─────────────────────────────────────────────────────────────────┐
  │  Django 5.2 + Django REST Framework + SimpleJWT                           │
  │  Порт: 8000 │ База: PostgreSQL (merchmarket_db) + SQLite для тестов       │
  └────────────────────────────────────────────────────────────────────────────┘
         │ HTTP
         ▼
  ┌─ Mobile ──────────────────────────────────────────────────────────────────┐
  │  Две реализации: 1) MerchMarketRN (Expo + кастомная навигация)            │
  │                   2) mobile/ (Expo + expo-router, file-based routing)      │
  │  Сборка: Expo SDK 56 │ Язык: TypeScript                                   │
  └────────────────────────────────────────────────────────────────────────────┘

  Файловая структура (корень: E:\илья проект\):

    ├── backend/          # Django API — 12 файлов, ~700 строк
    │   ├── config/       #   settings.py, urls.py
    │   ├── shop/         #   models.py, views.py, urls.py
    │   │   └── management/commands/  # seed_pg.py (241 стр.)
    │   └── manage.py
    │
    ├── frontend/          # Vite + React — 20 файлов, ~4300 строк
    │   ├── src/
    │   │   ├── components/  # Header (135), Marquee (36), ArtistIcons (175),
    │   │   │                 # CustomSvg (513 строк, 45 иконок)
    │   │   ├── pages/       # 9 страниц, ~2104 строк
    │   │   ├── context/     # AuthContext (153 строки)
    │   │   └── index.css    # 1645 строк — ПОЛНАЯ ДИЗАЙН-СИСТЕМА
    │   └── package.json
    │
    ├── MerchMarketRN/    # React Native (Expo + кастомная навигация) — 21 файл
    │   └── src/
    │       ├── screens/   # 9 экранов, ~1287 строк
    │       └── components/ # Header (294), CustomSvg (299), ArtistIcons (127)
    │
    ├── mobile/            # React Native (Expo + expo-router) — 19 файлов
    │   └── app/           # file-based routing, _layout.tsx, 8 экранов
    │
    └── fon.jpg            # Фоновое изображение, 138 KB


═══════════════════════════════════════════════════════════════════════════════
                   2. ФРОНТЕНД (Vite + React) — АНАЛИЗ
═══════════════════════════════════════════════════════════════════════════════

─── 2.1 Плюсы ────────────────────────────────────────────────────────────────

  [+] ПОЛНАЯ КАСТОМНАЯ ДИЗАЙН-СИСТЕМА
      Весь CSS (1645 строк) написан вручную, без Tailwind/Bootstrap. Это даёт
      полный контроль над каждым пикселем. ~62 CSS-переменные (цвета, тени,
      шрифты, радиусы). Все анимации кастомные (10 штук).

  [+] 45 СОБСТВЕННЫХ SVG-ИКОНОК
      CustomSvg.jsx содержит 45 уникальных иконок + 10 артист-иконок в
      ArtistIcons.jsx. Каждая иконка — hand-drawn стиль, что создаёт уникальную
      айдентику. Нет зависимостей от сторонних библиотек иконок.

  [+] УНИКАЛЬНЫЕ АРТИСТ-ИКОНКИ
      Каждый из 10 артистов имеет свою метафору-иконку:
      • GONE.Fludd — чупа-чупс (психоделика)
      • ЛСП — кассета с разбитым сердцем
      • Pharaoh — череп с короной
      • Oxxxymiron — корона с X.X.X.
      • Скриптонит — дом с числом 36
      • Гуф — весы с 825
      • Miyagi — горы с солнцем
      • Boulevard Depo — смайлик
      • ATL — лес, луна, волк
      • FACE — телевизор с лицом

  [+] ПРЕМИУМ ТЁМНАЯ ТЕМА
      Glassmorphism, золотые акценты, градиенты, шумовая текстура (SVG noise),
      кастомный скроллбар, анимации emberFlicker, riseIn, btnSheen.

  [+] JWT-АУТЕНТИФИКАЦИЯ С АВТО-РЕФРЕШОМ
      AuthContext управляет access/refresh токенами, автоматически обновляет
      токен при 401, сохраняет в localStorage.

  [+] ПЕРСИСТЕНТНОСТЬ КОРЗИНЫ И ИЗБРАННОГО
      cart и wishlist синхронизируются с localStorage через useEffect.

  [+] РЕАКТ-РОУТЕР V7
      9 маршрутов, правильные URL, поддержка /product/:id, редирект на "/".

─── 2.2 Минусы ───────────────────────────────────────────────────────────────

  [-] НЕТ TYPESCRIPT
      Весь фронтенд на чистом JSX. В проекте 4300 строк без типизации — это
      источник потенциальных багов, особенно при передаче пропсов между
      компонентами (items, artists, cart передаются через 4+ уровня).

  [-] index.css — 1645 СТРОК В ОДНОМ ФАЙЛЕ
      Весь CSS в одном монолитном файле. Сложно поддерживать, нет модульности.
      Даже при небольшом изменении приходится скроллить тысячи строк.

  [-] НЕТ АДАПТИВНОЙ ВЁРСТКИ
      Сайт явно заточен под desktop. Медиа-запросы есть только на 768px
      (нижняя навигация), но mobile-first подхода нет. На телефоне сайт
      смотрится неоптимально.

  [-] МОКОВЫЕ ДАННЫЕ VS API — РАСХОЖДЕНИЕ
      Фронтенд содержит 80 моковых товаров, бэкенд seed_pg.py генерирует 62.
      Структура данных различается (в моках есть поля вроде sticker_color,
      которых в API может не быть).

  [-] НЕТ ОБРАБОТКИ ЗАГРУЗКИ/SKELETON
      При загрузке данных с API нет скелетонов/лоадеров. Пока запрос идёт,
      показывается пустая страница.

  [-] НЕТ ОПТИМИЗАЦИИ ИЗОБРАЖЕНИЙ
      Сейчас все "изображения" товаров — SVG-заглушки NoPhoto. Реальных
      картинок нет. При их добавлении потребуется ленивая загрузка,
      ресайз, WebP, CDN.

  [-] ДУБЛИРОВАНИЕ ЛОГИКИ
      getStickerIcon определён 3 раза (Home, Catalog, ProductDetail — сейчас
      удалён, но раньше был). getConditionLabel продублирован. Это нарушает
      DRY.

  [-] НЕТ ТЕСТОВ
      Нет ни unit-тестов, ни e2e. Ни на фронте, ни на бэке.


═══════════════════════════════════════════════════════════════════════════════
                    3. БЭКЕНД (Django) — АНАЛИЗ
═══════════════════════════════════════════════════════════════════════════════

─── 3.1 Плюсы ────────────────────────────────────────────────────────────────

  [+] РАБОТАЕТ С ЛЕГАСИ-БАЗОЙ
      Модели Creator, Category, Product, ProductVariant, ProductImage — managed
      = False — мапятся на существующую БД. ShopUser маппится на users_user.
      Не требует миграций для основных таблиц.

  [+] JWT ЧЕРЕЗ SIMPLEJWT
      Правильная настройка: access 2ч, refresh 7д, Bearer-схема. Есть
      эндпоинт /token/refresh/.

  [+] CORS НАСТРОЕН
      Разрешены все origin'ы (для разработки). CSRF доверяет портам 5173 и
      8000.

  [+] ПРАВИЛЬНАЯ СТРУКТУРА
      Есть отдельное приложение shop, management commands для сидирования.

─── 3.2 Минусы ───────────────────────────────────────────────────────────────

  [-] НЕТ DRF СЕРИАЛИЗАТОРОВ
      Все view используют raw JsonResponse с ручной сборкой словарей. Это
      означает: нет валидации, нет документации (swagger), нет генерации
      схемы, сложно поддерживать. Вместо Django REST Framework используется
      как обычный HTTP-обработчик.

  [-] НЕТ АУТЕНТИФИКАЦИИ НА БОЛЬШИНСТВЕ VIEW
      Только /auth/profile/ защищён JWT. /checkout/ — csrf_exempt без
      аутентификации. Любой может отправить запрос на оформление заказа.

  [-] CHECKOUT НЕ СОЗДАЁТ ЗАКАЗ
      view checkout_order уменьшает stock у ProductVariant, но НЕ создаёт
      запись в таблице Order и OrderItem. То есть заказ "оформляется", но в
      БД не сохраняется. Это критический баг.

  [-] НЕТ ВАЛИДАЦИИ ВХОДНЫХ ДАННЫХ
      register_user и login_user парсят body через json.loads без proper
      валидации (нет проверки на длину username, формат email, сложность
      пароля). Django Rest Framework serializers решили бы это.

  [-] ДВЕ БАЗЫ ДАННЫХ
      Есть SQLite (db.sqlite3) и PostgreSQL (merchmarket_db). settings.py
      настроен на PostgreSQL, но SQLite остался в корне — путаница.

  [-] SQL_ASCII ENCODING
      База использует SQL_ASCII client_encoding — это может вызвать проблемы
      с кириллицей при сортировке и поиске.

  [-] ВСЕ VIEW @csrf_exempt
      Это нормально для API, но означает, что нет никакой защиты кроме JWT
      (который используется только на profile).


═══════════════════════════════════════════════════════════════════════════════
                 4. MOBILE (React Native) — АНАЛИЗ
═══════════════════════════════════════════════════════════════════════════════

─── 4.1 Плюсы ────────────────────────────────────────────────────────────────

  [+] СДЕЛАН ПЕРЕНОС ВСЕХ ЭКРАНОВ
      Все 9 страниц фронтенда портированы в React Native (Home, Catalog,
      ProductDetail, Cart, Wishlist, About, Profile, Login, Register).

  [+] ТИПИЗАЦИЯ (TypeScript)
      В отличие от фронтенда, RN-версия написана на TypeScript с интерфейсами
      для пропсов (IconProps, AuthContextType).

  [+] КАСТОМНЫЙ НАВИГАЦИОННЫЙ СТЕК
      В MerchMarketRN — собственный viewStack с push/goBack, без зависимости
      от React Navigation (который сложно настраивать). ProductDetail
      открывается поверх любого экрана.

  [+] ДВЕ РЕАЛИЗАЦИИ
      Есть MerchMarketRN (кастомная навигация) и mobile/ (expo-router).
      Expo-router — более современный подход с file-based routing.

  [+] ТЕМНАЯ ТЕМА ВОСПРОИЗВЕДЕНА
      theme.ts содержит COLORS, FONTS, SPACING, RADIUS, commonStyles,
      stickerCard — всё то же самое, что и в CSS фронтенда.

─── 4.2 Минусы ───────────────────────────────────────────────────────────────

  [-] ДВЕ RN-РЕАЛИЗАЦИИ — ЭТО ПРОБЛЕМА
      Есть MerchMarketRN и mobile/ — два разных проекта с разным подходом.
      Это удваивает объём поддержки. Нужно выбрать один и удалить второй.

  [-] НЕТ НАСТОЯЩЕЙ НАВИГАЦИИ (MerchMarketRN)
      Кастомный viewStack не поддерживает:
      • Жесты (свайп назад)
      • Deep linking
      • Анимации переходов (stock Animated вместо shared element transitions)
      • URL-роутинг (нельзя открыть ссылку /product/5)

  [-] НЕТ ОФЛАЙН-РЕЖИМА
      При отсутствии интернета приложение показывает пустоту. Нет кэширования
      данных через AsyncStorage/MMKV.

  [-] НЕТ ПУШ-УВЕДОМЛЕНИЙ
      Для мерч-приложения пуши (новые поступления, скидки) — essential.

  [-] АНИМАЦИИ НА Animated (не Reanimated)
      В drawer используется react-native Animated, а не Reanimated (который
      установлен). Reanimated даёт 60fps анимации на UI-потоке.

  [-] НЕТ ТЕСТОВ
      Как и везде.

  [-] mobile/ ПРОЕКТ НЕ ДОДЕЛАН
      В нём меньше фич, чем в MerchMarketRN. Нет экранов About, нет
      полноценного каталога с фильтрами, меньше моковых данных.


═══════════════════════════════════════════════════════════════════════════════
                   5. ОБЩИЕ ПРОБЛЕМЫ И РИСКИ
═══════════════════════════════════════════════════════════════════════════════

  ⚠ Git не инициализирован
    Нет контроля версий. Невозможно откатиться, нет истории изменений.

  ⚠ Нет .gitignore в корне
    node_modules, venv, __pycache__, dist — всё будет попадать в репозиторий.

  ⚠ Нет CI/CD
    Нет автоматической сборки, линтинга, деплоя.

  ⚠ Код на русском
    Названия переменных, комментарии, строки — всё на русском. Это нормально
    для соло-проекта, но при подключении других разработчиков вызовет
    трудности.

  ⚠ Мёртвые зависимости
    framer-motion и lucide-react в package.json не используются. Добавляют
    ~20 KB в бандл.

  ⚠ Нет линтера
    Нет ESLint, Prettier, Stylelint. Разный стиль кода в разных файлах.
